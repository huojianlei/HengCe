## 二、移植范围

**移植（17 个文件）**：data_ingest、file_extract、report_parse、llm_clean、rolling_budget、variance、
planning_operational、loop_decision、building_blocks、bsc、kpi、suyuan、zhenggai、kanban、xishu、baogao
＋新增 int-math（BigInt 半进位助手：TS number 乘法中间量可超 2^53，Python 大整数无此问题，必须集中封装）。

**不移植（3 个文件，理由）**：
- `model_api.py` / `moxing_peizhi.py`：dsh 原生 llm 适配器 + 凭据链已覆盖（见裁决 #11）；其测试的请求构造/密钥遮盖语义由 dsh 自身测试守护。
- `baogao_docx.py`：见裁决 #12。
- `tools/gen_data.py`、`tools/check_comments.py`：Python 工具链，不属插件本体。

**测试**：22 个测试文件中 19 个移植（上述 3 个不移植模块的测试除外）；期望值逐字保留。

## 三、已知口径漂移的修正

1. Python `baogao.py` 单元3脚注文案「5%黄/10%红」是历史残留——TS 版改为**由常量动态生成**
   （`黄档 ${HUANG_YUZHI_BPS/100}% / 红档 ${HONG_YUZHI_BPS/100}%`），杜绝再次漂移。
2. `examples/quanliucheng.py` 的 fixtures 旧 JSON 与 docstring 锚点是旧阈值时代产物——TS 版示例以
   tests 期望值为唯一锚点，fixtures 不移植，示例输出直接打控制台。

## 四、智能体层（persona 提示词）要点

写进 `ctx.systemPrompt.section`（order 0 persona 段）：预算助手身份、八步主线顺序（录入→滚动→差异→判定→双模型→溯源→看板→报告）、
缺数必须向用户询问（模块只报缺数，询问在应用层）、整数分/基点口径、双环修订案必须人工审批后下期生效。
把关台（tools/pre-execute 留档审计）列为后续增强，本次不实现。
