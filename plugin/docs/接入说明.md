# 衡策 UI · DSH 插件接入说明

更新：2026-10-18。交付对象：将现有后端封装为 DSH 插件的开发者，以及负责宿主与 UI 拼接的 agent。

配套类型见 `界面契约.d.ts`。通过 `?embedded=1` 可隐藏独立侧栏并采用业务页签布局。

本目录是独立的静态 ESM 前端。当前可以在浏览器运行演示数据与界面交互；它没有安装 DSH 插件，也没有与真实 DSH 运行时联调。下述 `hengceHost` 是本次 UI 定义的适配协议，不是对 DSH 官方 API 的声明。拼接时请根据实际宿主提供的插件视图、IPC、文件和会话能力实现该协议。

## 1. 分工与数据路径

```text
衡策界面（index.html + src/）
    ↓ window.hengceHost.request(action, payload)
宿主适配器（由拼接 agent 实现）
    ↓ 当前 DSH 支持的进程 / IPC / 插件工具机制
衡策插件（本地文件、持久化、Python 调度、AI 结果白名单）
    ├─ import_excel_v11 → 两册合并与权威清洗
    ├─ yinqing.fenxi → 已有分析算法
    └─ compute_report_pipeline → 报告与宿主 PDF 导出
    ↓ 原始结果序列化 + normalized workspace 适配
衡策界面展示完整返回状态
```

- UI 负责布局、筛选、表单、人工确认、图表与结果展示。演示模式的提示、示例状态变化不构成实际财务计算。
- 插件负责工作簿本地解析、校验、主体/情景分组、权威计算、历史快照、整改与修订记录、真实报告和文件读写。
- 宿主负责模型连接、会话生命周期、消息传递、工具权限、取消生成等基础能力。现有 UI 的 AI 区通过 `assistant.ask` 交给宿主，可在拼接时复用宿主原生对话区域。
- 不修改 `开发分支_1.0.5/algo`、既有 Python 算法或 `ingest_v11/模板` 契约。把 Python 包装成插件不需要重新实现计算逻辑。
- 页面不能直接 import Python。文件系统访问和进程调用由宿主或插件完成。

## 2. 宿主桥接入口

在 UI 的模块脚本首次运行**之前**注入桥接对象：

```js
window.hengceHost = {
  version: '1.0',
  async request(action, payload) {
    // 此处调用实际宿主适配器。
    // 返回 action 对应的结果；失败 reject 一个含中文 message 的 Error。
    return dispatchToHengcePlugin(action, payload);
  },
  subscribe(callback) {
    // 可选：把真实宿主事件转换为本说明的事件形状。
    // 必须返回解除订阅函数。
    return subscribeToHengcePlugin(callback);
  },
};
```

`dispatchToHengcePlugin` 与 `subscribeToHengcePlugin` 只是占位函数名，不在本项目实现。若宿主采用隔离上下文，请在受控 preload/等效桥接层暴露最小接口，不需要为页面开放 Node 或整个文件系统。

模式由 `src/业务桥.mjs` 加载时确定：

| 启动条件 | 行为 |
| --- | --- |
| 无 `window.hengceHost` | 演示模式，使用本地示例数据，明确展示演示标记 |
| 有合法桥接对象 | 宿主模式，所有业务请求交给 `request` |
| 有桥接对象但版本或方法不符 | 报接入错误，不回退为演示数据 |
| 宿主请求失败 | 显示失败信息，保留可检查的现有页面，不用演示值冒充成功 |

桥接对象是启动依赖；启动后再赋值需要重新加载 UI。即使没有事件订阅，也应能通过每次请求返回完整 workspace 工作。

## 3. 请求与返回约定

除下载、打开目录与 AI 操作外，每次成功的业务变更返回**完整 normalized workspace**，而不是 JSON Patch。UI 用这个结果替换当前工作区，从而同时更新看板、差异、整改、报告与记录。

| action | payload | 成功返回 | 插件要完成的工作 |
| --- | --- | --- | --- |
| `workspace.load` | `{}` | 完整 workspace | 读取当前主体、输入、结果和持久化状态 |
| `files.import` | `{files:[{name,size,bytes}],mode,category}` | 完整 workspace | 本地校验 xlsx，按主体、情景、期间归组，更新导入信息与 dirty 状态 |
| `files.remove` | `{id}` | 完整 workspace | 移除指定导入项，重新检查分析所需输入 |
| `templates.download` | `{category}` | 下载响应 | 读取真实标准空白模板，保留契约内容 |
| `analysis.run` | `{entityId,config}` | 完整 workspace | 映射配置、调用权威分析、保存运行结果和历史快照 |
| `background.save` | `{changeStatus,text}` | 完整 workspace | 保存经营变更确认和补充背景；不把自由文本自动认定为正式变更台账 |
| `actions.update` | `{id,status}` | 完整 workspace | 保存整改状态，调用计数回算，更新组织与看板汇总 |
| `revisions.approve` | `{rowId,period,amount,reason,approved:true}` | 完整 workspace | 核对科目、未来期间、金额和确认状态，保存修订并使用既有链式重算 |
| `reports.generate` | `{runId,includeAI}` | 完整 workspace | 对指定有效运行组装报告；需要 AI 时调用宿主，记录生成结果 |
| `reports.export` | `{id,format}` | 下载响应 | 导出实际 `pdf`、`html`、`md` 或 `json` 文件 |
| `reports.openFolder` | `{id}` | `{handled:true}` | 由宿主打开该报告的实际输出目录 |
| `history.open` | `{id}` | 完整 workspace | 加载对应历史运行的完整快照，不能只换标题 |
| `assistant.ask` | `{question,context,dataAccess}` | AI 响应 | 权限检查、结果白名单化、宿主会话调用 |

字段细则：

- `files[].bytes` 是 `ArrayBuffer`，`size` 是文件字节数。`mode` 为 `append` 或 `replace`；`category` 为四类工作簿之一或 `null`。文件名及用户所选类别仅作提示，最终类别和校验结论由工作簿解析器确定。
- 如果底层 IPC 只支持 JSON，由适配器显式转换二进制并校验长度；不能直接 `JSON.stringify(ArrayBuffer)`，否则字节会丢失。输入内容仅在本机解析。
- `actions.update.status` 为 `pending`、`doing`、`done`，分别映射 Python 的 `待整改`、`进行中`、`已完成`。
- `revisions.approve.amount` 为安全整数**分**，不是输入框上显示的元。`approved:true` 代表本机人工确认，不代表多人审批完成。插件仍须校验已届满期间不可修改。
- `assistant.ask.context` 为 `{entityId,period,rowId?,runId}`。`dataAccess` 为明确布尔值，不能因存在上下文 ID 而默认为授权。
- `reports.generate.includeAI` 只表示请求包含 AI 解读；真实完成、失败和未回填状态需要如实返回，不能以占位文案宣告完成。
- `demo.reset` 是仅演示模式使用的本地命令，宿主无需实现。

下载响应只有两种形状：

```js
{ name: '报告.pdf', mime: 'application/pdf', bytes: arrayBuffer }
// 或：宿主已完成原生保存/下载流程
{ handled: true }
```

正式报告预览复用 `reports.export({id,format:'html'})`：UI 将返回的 HTML 字节用 UTF-8 解码，放入 `sandbox=""` 的 iframe。该预览不会调用本地演示报告模板。为支持页面内预览，宿主应返回完整自包含 HTML 字节（样式与图片不依赖宿主磁盘相对路径）；返回 `{handled:true}` 时代表宿主已实际接管展示或导出。当前协议没有单独的 preview action，若宿主需要区别“预览 HTML”与“下载 HTML”，可后续共同升级协议。

不要把宿主绝对路径直接当作浏览器可读取 URL。报告生成成功也不意味着 PDF 已存在，PDF 导出要以真实打印/导出结果为准。

AI 响应：

```js
// 在衡策面板展示结果，sources 为可选的真实引用
{ text: '实际模型回复', sources: [{ title: '来源名称', excerpt: '来源摘要' }] }
// 或：宿主原生会话已接管本次提问
{ handled: true }
```

`handled:true` 表示请求确实被宿主接管，不能用于掩盖未实现操作。如果改用事件回填面板消息，应避免同步响应与事件重复展示同一回复。

## 4. 事件与错误

可选 `subscribe(callback)` 接收以下事件：

```js
{ type: 'workspace.changed', data: workspace }
{ type: 'analysis.progress', data: { message: '正在计算差异', percent: 60 } }
{ type: 'assistant.message', data: { text: '实际宿主回复' } }
```

进度 `percent` 使用 0～100；数据来自真实执行阶段。工作区事件也必须携带完整 normalized workspace。订阅解除函数需清理对应监听器，防止视图重挂载后重复回填。

请求失败使用 Promise rejection：

```js
throw new Error('分析期间格式与滚动周期不一致');
```

`ExcelError`、`YinqingCuowu` 的中文业务信息应保留。其他 I/O、协议或进程异常转换为可理解的错误，并在宿主日志保留调试信息；不要返回 `{ok:false}` 冒充正常 workspace。宿主模式发生超时、无权限、格式错误或计算失败时，不能自动返回演示数据。

## 5. normalized workspace 与显示口径

UI 数据结构以同目录 `src/演示数据.mjs` 的 `createDemoData()` 返回对象为可执行样例。接入时应逐字段适配，不要把 Python 原始返回值直接塞入 UI，也不要依赖字段名看似相近就认为结构相同。

当前 normalized workspace 字段：

| 字段 | 形状 |
| --- | --- |
| `schemaVersion` / `demo` / `dirty` | `'1.0'` / 布尔值 / 布尔值；真实接入设 `demo:false`，初始未变更设 `dirty:false` |
| `meta` | `{company,period,scenario,generatedAt,runId}` |
| `config` | `{cycle,period,growth,industry,industryCorrection,industryThreshold,noise,significance,tiers:[{name,color,threshold}]}` |
| `entities` | `[{id,name}]`；当前 UI 用部门 ID 筛选，`all` 表示全部部门 |
| `files` | `[{id,name,category,status,checks,rows,size,entity}]` |
| `rows` | `[{id,subject,module,department,departmentId,period,budget,actual,variance,rate,risk,direction,decision,reason,source}]` |
| `trend` | `[{period,budget,actual,rolling}]`；`actual` 或 `rolling` 缺失用 `null` |
| `actions` | `[{id,rowId,title,department,owner,due,status,priority,type,description}]` |
| `revisions` | `[{id,rowId,period,amount,reason,approved,subject,createdAt}]`；演示记录另有 `demo:true` |
| `reports` | `[{id,title,period,createdAt,status,format,pages,includeAI?,demo?}]` |
| `history` | `[{id,period,createdAt,company,status,riskCount}]` |
| `kpis` | `[{name,value,unit,note}]`；当前百分比 `value` 为 bps，缺值用 `null` |
| `background` | `{changeStatus,text}`；UI 变更状态使用 `'yes'` / `'none'` / `'unknown'` |

UI 枚举与细节：

- `rows.module` 为 `收入`、`成本`、`费用`、`采购`；对应 Python 的 `收入模块` 等名称需要去除展示后缀。采购为独立管理视角，不应在收入减成本减费用之后再次扣除来计算利润。
- `rows.risk` 为 `high`、`watch`、`normal`；`direction` 为 `favorable` / `unfavorable`；中性差额需由 adapter 与 UI 协调明确的展示状态，不靠数值符号猜测方向。Python `F/A/N` 与 UI 枚举需要显式映射。
- `rows.decision`、`reason` 和 `source` 是展示文本。真实实现应把判定代码与中文展示建立映射；不要照抄演示的“单环纠错”等措辞作为后端枚举。
- `files.status:'valid'` 表示后端已经校验通过；`pending` 表示尚待真实校验。校验失败应报错并保留可定位的失败信息，不能标记 `valid`。
- workspace 的 `files.size` 可为示例中的可读字符串或字节数；导入请求的 `files[].size` 必须是数字字节数，两者不要混淆。
- `actions.status` 使用 `pending/doing/done`；示例 `priority` 为 `high/watch`，`type` 为 `revision/execution`。完整低优先级及其他算法整改类型应在接入时显式映射和验收。
- `reports.pages` 未实际生成时使用 `null`，不得复制示例的页数。`history.id` 必须能取回该次运行的真实快照。
- UI 的 `background.changeStatus` 不能直接透传给 Python：Python 使用 `unknown/none/provided/pending`。`yes` 应结合真实经营变更台账是否完整映射为 `provided` 或 `pending`；仅填写背景文本不能直接认定 `provided`。
- 如果需要额外的 `warnings`、校验条目、真实报告 HTML、完整溯源等字段，可在 adapter 中附加，并与 UI 消费入口一起接线；原始 Python 返回非空不等于页面自动支持该字段。

需要保留的共同约定：

- 金额使用整数分；显示元时除以 100，万元时除以 1,000,000。金额输入转换回分后再发往桥接层。
- 比率使用整数基点（bps）；显示百分比时除以 100。例如 `2500` 代表 `25%`，不是 `0.25%`。
- JavaScript 数据必须满足 `Number.isSafeInteger`。Python 无限精度整数超过安全范围时应明确报错或另行升级协议，不得静默截断。
- 期间使用 `YYYY-MM` 或 `YYYY-Qn`，必须与周期匹配。时间戳建议 ISO 8601，源时间戳不应被本地显示文本覆盖。
- ID 要能稳定定位主体、来源工作簿、差异行、整改项、修订、报告和历史运行。生成历史快照时保存相应 ID 关联。
- 缺失数据使用 `null` 或明确空数组/不可用状态，不得将缺失值填 0 造成“已计算”的错觉。
- 行级预警、F/A 方向、单双环判断、金额与比率均来自后端。前端可以排序筛选、格式化与画图，不重新判定财务结论。
- 配置页以百分比显示，桥接配置以 bps 传递。UI 的预警档位属性需要在适配层映射为 Python `ming_cheng`、`yan_se`、`yu_fen`，同时保留名称、颜色、阈值的原始含义。
- `dirty` 表示输入、背景或分析配置与已生成结果不一致。后端成功重算后清除；报告应绑定明确 `runId`，不得对未重算的输入生成旧结果报告。

依据文件：

- `D:/AppProject/开发分支_1.1.1/houtai_hexin_python/导览-后端核心Python版.md`

推荐在插件侧集中实现一个 adapter：原始工作簿 → 导入结果 → 分析输入 → 原始分析结果 → normalized workspace。UI 内不复制这些算法。

### 6.1 导入与分析

1. 调用 `import_excel_v11(data: bytes, name: str)`，读取真实 `category`、`metadata`、`checks`、`ruku_shu`、`groupKey`、`subjects` 及记录。扩展名必须 `.xlsx`。
2. 必需输入为预算基础与实时经营两册；行业对标和经营变更按需加入。按主体、情景及批次口径合并，避免跨主体数据混算。
3. 多册合并沿用权威 CSV 清洗链 `data_ingest.daoru_csv`，去除重复表头。拒绝清单 `jujue` 非空时不得继续分析。
4. 组装 `company`、`metadata`、`records`、`subjects`、`config` 等输入，再调用 `yinqing.fenxi(shuru, xiuding_lie)`。组织批量分析沿用 `analyze_subjects` / `zuzhi_huizong` 的既有编排。
5. 保存原始结果，供报告、AI 边界和追溯使用；另构造 UI workspace。不要仅保存页面聚合结果而丢失原始计算快照。

Python 的 `variance/blocks/bsc/kpi/trace/dashboard/factors` 包含 dataclass，`correction` 为名字空间。JSON 输出前要递归处理 dataclass、字典、列表及 `SimpleNamespace`；不要用 `default=str` 把结构变成字符串。嵌套对象正确序列化后仍需要字段映射。

### 6.2 现有 19 个结果键的映射建议

此处按 `fenxi` 实际返回列出 19 键；`schemaVersion` 算一个键。表中“展示用途”是 adapter 的数据来源，不能取代实际 workspace schema。

| Python 原始键 | UI 数据与展示用途 | 适配要求 |
| --- | --- | --- |
| `schemaVersion` | 协议兼容性检查 | 当前原始结果为 `1.0`；与宿主桥版本分开校验 |
| `meta` | workspace `meta`、标题、期间、主体、运行时间 | 保留主体/情景编码、周期、单位、simulation；补充稳定 runId |
| `config` | workspace `config`、分析参数回填 | bps 不改变；映射预警档位字段并保留配置颜色 |
| `records` | 已校验原始记录、来源明细 | 本地保存；按需映射行级来源，不整体传给 AI |
| `subjects` | 科目模块索引、行级模块分类 | 为 variance/decision 连接模块提供依据 |
| `rolling` | 滚动预算、趋势与未来预算修订展示 | 逐科目、逐期适配；保留原始期间与实际/预测来源 |
| `variance` | 差异明细行、预警、预算/实际/差额/差率 | 展平数据类；不要将率、方向或预算字段重新计算成另一口径 |
| `moduleSummary` | 收入/成本/费用/采购汇总 | 与 `blocks` 的占比分母可能不同，保留原算法定义 |
| `splits` | 价差/量差或计划/执行差异拆分 | 无输入时显示不可用，不补造拆分结果 |
| `decisions` | 行级单双环判断、需审批标识、判定依据 | 按科目与期间关联差异行，保留依据快照 |
| `blocks` | 模块归因、积木分析明细 | 展平数据类，保持 D1–D3 原有口径 |
| `bsc` | BSC 能力状态 | 当前版本为 `None`，隐藏或显示未提供评分 |
| `kpi` | KPI/看板指标扩展 | 有真实输入才展示；不补造 KPI |
| `trace` | 溯源和来源查看 | 原结果键为单数 `trace`；输入可能叫 `traces`，勿混淆 |
| `correction` | workspace `actions`、整改状态/计数 | 实际是整改清单，不是行业修正；将 `qingdan` 和状态映射至 UI |
| `dashboard` | 经营概览、图表摘要 | 仅使用已有实际字段；原引擎部分区域可能为空结构 |
| `factors` | 完成率、预警分布、提示摘要 | 展平数据类；不能从演示固定文案推断真实结果 |
| `warnings` | 全局/结果提示条 | 原文保留，非空可见 |
| `revisions` | 修订记录、已批准修订回显 | 与运行、科目、期间、原因、时间绑定；审批后真正重算 |

`files`、报告列表、历史运行、用户输入背景等属于插件持久化与运行管理，不是 `fenxi` 单次输出自带的完整工作区数据，需要插件自行维护。

### 6.3 报告与 AI

- 继续调用 `compute_report_pipeline` 产出 Markdown / HTML。`wencai_hanshu` 与 `zongjie_hanshu` 未注入时会留下 DSH 回填占位；不能把该占位当成已完成 AI 解读。

- `includeAI` 和 AI 面板访问开关需要与宿主的授权状态核对。复用 `ai_bianjie.zhunbei_ai_qingqiu` 进行白名单结果 DTO 构造；原工作簿与原始备注不进入模型请求。已有后端边界层不能因 UI 存在开关而省略。
- 报告 `html`/`md` 返回路径由插件读取、校验并转换成 UI 所需预览/下载内容；真实 PDF 由宿主支持的打印或导出能力生成。

## 7. 渲染与宿主边界

- 正式报告预览复用 `reports.export({id,format:'html'})`。返回文件字节后，UI 在无脚本权限的沙箱 iframe 中呈现；若返回 `{handled:true}`，由宿主负责展示。UI 不把该 HTML 插入主文档。
- 自定义预警名称和颜色可通过差异行的 `tierName` / `tierColor` 返回，颜色必须为 `#RRGGBB`。`risk` 仍用于 high/watch/normal 筛选归组。实际预警采用后端判定；有利/不利方向与预警等级独立，不能把演示中简化的风险派生逻辑当成正式算法。
- `trend` 支持空序列、月度或季度期间以及 null 实际值。后端没有返回数据时，UI 显示空状态。
- 前端参数保存先标记本地 dirty；重新分析时把完整 config 提交宿主。dirty 状态下禁止生成新报告，已有报告按其 ID 预览原快照。

- 桥接仅从明确的宿主注入，业务动作使用白名单。不要使用不校验来源的 `window.postMessage('*', ...)`、任意方法执行或从页面传任意系统命令。
- 若实际 DSH 桥接必须通过消息传递，校验精确来源、窗口对象、动作、请求 ID 和负载结构，不能把未知页面消息当成插件授权。
- 工作簿内容、主体名、科目名、AI 回复、错误信息与引用都属于文本数据。使用安全文本渲染；如需 Markdown/HTML，使用可信净化与隔离预览，禁止把模型文本直接插入可执行 HTML。
- 报告外部链接和本地文件打开交给宿主明确的处理器；渲染进程无需接收任意路径读写能力。
- 本机人工确认是本版交互事实。若未来做多人审批，需要独立定义身份、权限、审批状态与审计链，不把当前 `approved:true` 当成该能力。

## 8. 接入验收清单

以下是**待真实宿主完成的接入验收**，不是本次静态 UI 已通过的后端测试结果。

| 场景 | 通过标准 |
| --- | --- |
| 无宿主启动 | 展示演示标记；示例操作与受限能力可识别 |
| 合法宿主启动 | 读取真实 workspace；不混入示例公司、金额、历史或回复 |
| 桥版本错误 / 插件异常 | 显示接入错误；不回退为演示成功 |
| 两册真实 xlsx 导入 | 显示解析所得主体、期间、类别、校验数与行数；必要输入齐全后才能分析 |
| 只有一册 / 科目被改坏 | 原样显示真实中文校验/分析错误；不产生有效运行记录 |
| 多主体与情景 | 不串账；切换主体、批量分析与汇总符合已有算法口径 |
| 分与 bps | 用已知夹具核对金额、万元显示、差率和参数；不存在 100 倍误差 |
| 预警档位变化 | 请求传正确 bps；真实重算后颜色、预警和整改一致更新 |
| 月度 / 季度 | period 格式与 cycle 一致；不兼容时可理解报错 |
| 运行进度与失败 | 进度来自执行事件；完成仅在完整结果返回后显示；失败可重试 |
| 来源 / 判断依据 | 差异行能连接真实工作簿来源和对应判定，不使用演示解释 |
| 整改状态 | 状态持久化，列表、统计和组织页一致回算 |
| 未来预算修订 | 输入元准确转分；必须确认与填原因；历史期间拒绝；批准后真正调用修订重算 |
| 报告生成 / 四格式导出 | 与指定 runId 对应；PDF 可打开且中文正确；HTML/MD/JSON 为真实内容 |
| AI 访问关闭 / 开启 | 关闭时无业务结果外发；开启只发白名单；真实宿主回复与来源回填 |
| 历史记录 | 打开对应完整快照；页面、参数、来源与报告关联相符 |
| 持久化与重新打开 | 文件、运行、整改、修订与报告在重启后按产品约定恢复 |
| 渲染注入检查 | 包含 HTML/脚本文字的文件名、科目、AI 回复不执行脚本 |
| BSC / 拆分缺输入 | 显示未提供或隐藏，不能展示伪造评分和拆分值 |

最小拼接顺序：先完成 `workspace.load` 与 Python→workspace adapter，再完成导入/分析，随后接整改与修订，最后接报告、宿主会话与历史恢复。每一步都使用同一套真实运行 ID 和来源关联。
