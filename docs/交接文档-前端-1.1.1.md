## 2. 三个接口（唯一需要对接的 Python API）

### 2.1 导入

```python
from excel_ingest_v11 import import_excel_v11

r = import_excel_v11(data: bytes, name: str)      # name 必须以 .xlsx 结尾
```

| 项 | 值 |
|---|---|
| 入参 | `data` = 文件字节；`name` = 文件名（只用于判定后缀与日志） |
| 自动分派 | 12 表（老契约）/ 9 表（v2 演示件）/ 外部两册（行业对标、经营变更） |
| 耗时 | 9 表 ≈ 1.5 s ｜ 12 表 ≈ 2.5 s |
| 异常 | `xlsx_reader.ExcelError` → `str(e)` 即可直接弹给用户（中文） |

返回键：

| 键 | 类型 | 前端怎么用 |
|---|---|---|
| `ok` | bool | 恒为 True（失败是异常，不会返回 False） |
| `contract_version` | str | `v2` / `v1.1` / `v1.2`；外部册无此键 |
| `category` | str | `预算基础` / `实时经营` / `行业对标` / `经营变更` |
| `metadata` | dict(16) | 见 §3.1，填"批次信息"卡片 |
| `checks` | int | 显示"校验 N 项通过" |
| `records` | dict(5) | 见 §3.2，喂给分析引擎 |
| `ruku_shu` | int | 入库行数 |
| `subjects` | list | 科目清单（v2 有 18 个） |
| `groupKey` | str | 合并多本时的分组键 |
| `text` | str | 八字段 CSV 原文（可导出留痕） |
| `three`/`shuijin`/`tanxiao`/`fenlu` | — | **仅 v2**：三表快照/税金分项/摊销台账/逐笔分录（明细页直接用） |

> ⚠️ **必须导两本**：`预算基础`（12 个月预算行）+ `实时经营`（已结账月实际行）。
> 只导一本 → 分析引擎会抛「请先导入年度预算」。

### 2.2 分析

```python
from yinqing import fenxi

jieguo = fenxi(shuru: dict, xiuding_lie: list | None = None)
```

`shuru` 必须字段（其余可留空）：

```python
shuru = {
    'company':  '恒暻信息技术有限公司',          # 报告抬头
    'metadata': {'主体名称': ..., '主体编码': ..., '情景名称': ..., '情景编码': ...},
    'records':  jilu,                            # §2.1 的 records（或两本合并后的）
    'subjects': r['subjects'],
    'config': {
        'cycle': '月度',                          # '月度' | '季度'
        'period': '2027-06',                      # 分析末档；季度用 '2027-Q2'
        'growth': 0,                              # 企业增长率（基点，100 = +1%）
        'industry': None,                         # 行业增长率（基点）；None = 不启用
        'industryCorrection': False,              # 季度是否启用行业修正
        'industryThreshold': 50,                  # 行业修正门限（基点）
        'noise': 2500,                            # 噪声门限（基点）
        'significance': 2500,                     # 显著性门限（基点）
        'tiers': [                                # 预警档位（必须升序、颜色 #RRGGBB）
            {'ming_cheng': '黄', 'yan_se': '#FFAA00', 'yu_fen': 1500},
            {'ming_cheng': '红', 'yan_se': '#FF0000', 'yu_fen': 3000},
        ],
    },
    # 暂无对应功能时传空：
    'bsc': None, 'kpi': {}, 'traces': [], 'splits': [], 'events': [],
    'baselines': [], 'changeStatus': None,
}
```

返回 19 键（金额单位＝**分**，比率单位＝**基点**，`schemaVersion='1.0'`）：

| 键 | 类型 | 页面 |
|---|---|---|
| `meta` | dict(13)：company/period/scenarioName/entityCode/generatedAt/moneyUnit/rateUnit/simulation | 抬头 |
| `config` | dict(9) | 表单回填 |
| `rolling` | list(18) | 滚动预算表（每期一条） |
| `variance` | `ChayiJieguo` | 差异/预警页 |
| `decisions` | list(108) | 整改清单 |
| `blocks` | `JimuJieguo` | 积木（价差/量差） |
| `dashboard` | `KanbanShuju` | 看板卡片 |
| `factors` | `XishuBao` | 系数包（完成率、预警分布） |
| `kpi` | `KpiJieguo` | KPI 页 |
| `bsc` | None（本版未评分） | 可隐藏 |

| `warnings` | list(4) | 顶部黄色提示条 |

## 4. 建议的界面结构（4 个视图）

| 视图 | 内容 | 依赖数据 |
|---|---|---|
| **① 导入** | 拖两本 xlsx（预算基础/实时经营）→ 显示主体名、期间、校验 N 项、入库行数；错误原样弹出 | `metadata` / `checks` / `ruku_shu` |
| **② 配置** | 周期（月/季）、分析末档、增长率、三个门限、预警档位（色+阈值可增删） | 提交成 `config` |
| **③ 结果** | 顶部：完成率、预警分布（红/黄/无）、核心问题模块；主体：滚动预算表、差异明细（按差额排序，行级标色）、整改清单（按优先级分组） | `factors` / `rolling` / `variance` / `decisions` |
| **④ 报告** | 预览 `html`（iframe）→「导出 PDF」→ 打开所在目录 | `compute_report_pipeline` 返回 |

交互细节建议：

- 金额展示：`分 → 元`（÷100，两位小数，千分位）；比率 `基点 → %`（÷100）。
- 预警配色直接用 `config.tiers[].yan_se`，不要自己另定色板。
- `warnings` 非空时在结果页顶部放可折叠提示条（内容原样展示）。
- 导入失败/分析失败：只捕获 `ExcelError` 与 `YinqingCuowu`，`str(e)` 直接展示，不要翻译成自定义文案。

## 5. 运行时架构建议

```
Electron 主进程（Node）
  ├─ spawn: 打包后的 Python（PyInstaller --onedir）
  │     · 方式 A：命令行 + JSON 文件交换（简单，推荐先做）
  │     · 方式 B：本地 HTTP（127.0.0.1 随机端口）暴露三个接口（体验更好）
  └─ 渲染进程（前端页面）↔ IPC ↔ 主进程 ↔ Python
```

- Python 侧入口：`跑衡策全流程.py`（全链 CLI）或自建一个 `server.py` 包装三个函数
- **不要**在渲染进程直接读文件系统；文件选择走 Electron dialog
- 输出目录：`报告组装\输出\`（md/html/pdf 同名，重跑覆盖）
- 单次全链耗时：导入 ~3 s + 分析 ~3 s + 报告 ~1 s + PDF ~2 s ≈ **10 s**（一万级格校验在内）

## 7. 附录 A：可直接跑的最小后端脚本（联调用）

```python
# demo_server.py —— 把三个接口串起来的最小实现（前端可先按这个联调）
import sys, json
from pathlib import Path

ROOT = Path(r'D:\AppProject\开发分支_1.1.1')
for p in (ROOT / 'ingest_v11', ROOT / 'houtai_hexin_python', ROOT / '报告组装',
          Path(r'D:\AppProject\开发分支_1.0.5\algo')):
    sys.path.insert(0, str(p))

from excel_ingest_v11 import import_excel_v11
from data_ingest import daoru_csv
from yinqing import fenxi
from baogao_liuxian import compute_report_pipeline


def pao(luyu: Path, lushi: Path, config: dict, mu: Path):
    a = import_excel_v11(luyu.read_bytes(), luyu.name)
    b = import_excel_v11(lushi.read_bytes(), lushi.name)
    wen = a['text'] + '\n' + '\n'.join(b['text'].splitlines()[1:])
    jilu = daoru_csv(wen)

    shuru = {'company': a['metadata']['主体名称'], 'metadata': {
                 '主体名称': a['metadata']['主体名称'], '主体编码': a['metadata']['主体编码'],
                 '情景名称': a['metadata']['情景名称'], '情景编码': a['metadata']['情景编码']},
             'records': jilu, 'subjects': a['subjects'], 'config': config,
             'bsc': None, 'kpi': {}, 'traces': [], 'splits': [], 'events': [],
             'baselines': [], 'changeStatus': None}
    jieguo = fenxi(shuru)
    bao = compute_report_pipeline(jieguo, shuchu_mu=str(mu))
    return {'meta': jieguo['meta'], 'warnings': jieguo['warnings'],
            'decisions': len(jieguo['decisions']), 'report': bao}


if __name__ == '__main__':
    mu = ROOT / '报告组装' / '输出'
    cfg = {'cycle': '月度', 'period': '2027-06', 'growth': 0, 'industry': None,
           'industryCorrection': False, 'industryThreshold': 50,
           'noise': 2500, 'significance': 2500,
           'tiers': [{'ming_cheng': '黄', 'yan_se': '#FFAA00', 'yu_fen': 1500},
                     {'ming_cheng': '红', 'yan_se': '#FF0000', 'yu_fen': 3000}]}
    r = pao(ROOT / '演示生成器v2/输出/演示-预算基础-20261018.xlsx',
            ROOT / '演示生成器v2/输出/演示-实时经营-20261018.xlsx', cfg, mu)
    print(json.dumps({k: r[k] for k in ('meta', 'decisions', 'report')},
                     ensure_ascii=False, indent=2, default=str))
```

## 8. 附录 B：常见坑

| 现象 | 原因 / 解法 |
|---|---|
| `请先导入年度预算` | 只导了实时经营（没有预算行）；两本都要导 |
| `分析期间格式与滚动周期不一致` | `cycle='季度'` 时 `period` 必须是 `YYYY-Qn` |
| 报告里条例全是「未检索到直接依据」 | 缺 `numpy/onnxruntime` 或 kb2 资产；不是前端问题 |
| 报告「分析内容」是占位文案 | 未注入 `wencai_hanshu`（设计如此） |
| PDF 中文变方块 | 打印引擎没装中文字体；Windows 用系统同款（微软雅黑）即可 |
| 打开 xlsx 是空的 | 分录/摊销已平移到 A1 起，旧格位（O121）不再有数据 |
| 数字差 100 倍 | `records.shuzhi` 是**分**，展示要 ÷100 |
